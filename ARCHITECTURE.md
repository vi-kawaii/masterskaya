# ARCHITECTURE.md

Общие архитектурные решения для всех проектов мастерской `D:\rust\`.

Файл фиксирует паттерны, которые переиспользуются между проектами.
Правки — только осознанно, потому что они влияют на всё сразу.

---

## Паттерн: base ⊕ runtime overlay

**Проблема.** Play/анимация/трекинг не должны портить базовое состояние
документа. Иначе после выхода из Play модель останется в позе, в которой
её застало выключение.

**Решение.**
- Документ — источник истины для базового трансформа.
- Runtime-слой живёт в отдельном компоненте (`Runtime`, `Overlay<T>` и т.п.).
- Итог сцены = `base ⊕ runtime`.
- Выход из Play = `runtime = default()`, базовая поза восстанавливается
  из документа.

**Где применять.** Любой проект, где есть «режим воспроизведения»
поверх редактируемых данных: редактор анимации, игра с позами,
трекинг.

**Реализация.** См. `v/src/types.rs` — `RuntimeTransform`, `Runtime`,
`v/src/playback.rs` — композиция.

## Паттерн: Loading — это стейт, а не таймер

**Проблема.** Загрузка в фоне на таймере даёт рассинхрон: UI уже
показал игру, а ассеты ещё грузятся.

**Решение.** `Loading` — отдельное состояние приложения. Переход
`Loading → Main` только когда всё реально загружено. Пока загрузки нет —
таймер как заглушка, но с прицелом на реальный `AssetServer`.

**Где применять.** Все проекты. Никаких «подождём 5 секунд и поехали».

## Паттерн: AGENTS.md — в корне мастерской

**Проблема.** В каждом проекте свой `AGENTS.md`, они расходятся,
ИИ получает разные инструкции.

**Решение.** Общие правила — один `D:\rust\AGENTS.md`. Проектные
`AGENTS.md` создаются только если у проекта есть **специфика**,
которую нельзя выразить общим файлом.

---

## Общие крейты (`libs/`)

Все крейты — независимые, подключаются через `path` из проектов.

- `libs/app-shell` — каркас Bevy-приложения (окно, FPS-оверлей,
  ClearColor, профиль сборки).
- `libs/loading` — экран загрузки с прогресс-баром (в работе).
- `libs/fps-overlay` — FPS-оверлей (сейчас внутри app-shell).
- `libs/status-text` — статус-текст в углу экрана (в работе).
- `libs/bevy-ext` — мелкие хелперы (конверсии, apply_transform и т.п.).

**Правило.** Крейт создаётся, когда одна и та же **суть** повторяется
в двух и более проектах. Не раньше.

---

## Что НЕ выносить в `libs/`

- Доменные типы (`MeshObject`, `GameSettings`, `CameraRig`).
- Состояния приложения (`AppState`, `GameState`) — они разные.
- Логику конкретного проекта (`editor`, `playback`, `controller`).

Это либо разное, либо обёртки над Bevy, которые не несут твоих решений.

---

## Правила для нового проекта

1. Создать `D:\rust\<name>\` через `cargo new`.
2. `main.rs` — через `lab_app_shell::build_app(...)`.
3. Зависимости на `libs/*` — через `path = "../libs/<name>"`.
4. `AGENTS.md` — только если есть специфика.
5. `DESIGN.md` — свой, живой роадмап.
6. Общие паттерны (base ⊕ runtime, Loading-стейт) — использовать
   по умолчанию.
